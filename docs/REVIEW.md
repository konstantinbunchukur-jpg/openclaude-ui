# Обзор OpenClaude UI

## Вывод

Архитектура соответствует задаче: встроенный HTTP-сервер Node.js, обычный HTML/CSS/JS,
CLI как дочерний процесс и SSE для событий. React, сборщик, база данных и Docker
сейчас не нужны. Главный приоритет — защита локального API и сохранность файлов,
затем корректность запуска CLI и восстановления чата; редизайн можно отложить.

Это ревью исходников и изолированные HTTP/CLI-проверки, не полноценный пентест.
Таблица ниже фиксирует исходное состояние; четыре P0 с тех пор исправлены.

## Статус P0 (исправлены)

`npm run test:security` проходит **7 из 7**:

- `POST /api/upload` создаёт файл эксклюзивно (`flag: 'wx'`) и отвечает `409`, а не перезаписывает;
- листинг и загрузка проверяют канонические пути (`realpath`): junction и symlink не выводят за рабочую папку;
- без явно заданной непустой рабочей папки `/api/files` и `/api/upload` отвечают `400`;
- CLI запускается отдельными argv без shell-строки, сообщение уходит через stdin pipe, а Windows `.cmd`-шим запускается через `cmd.exe` с массивом аргументов.

Остались защита в глубину (`open-terminal`/`open-folder`, `NODE_OPTIONS`), маскирование
секретов в `/api/state` и P1/P2 ниже. Актуальные результаты — в конце документа.

## Цепочки выполнения кода (RCE)

> **Статус:** общая HTTP-граница сделана (`trustedApiRequest` в `server.js`): для всех
> `/api/*` проверяются Host, Origin, `Sec-Fetch-Site`, а POST принимается только с
> `application/json` или `application/octet-stream`. Это закрывает все цепочки ниже для
> чужих страниц; тест цепочки № 1 зелёный. Запуск CLI, `auth` и `install` больше не
> используют shell-строку. Защита в глубину для `open-terminal`/`open-folder` и
> `NODE_OPTIONS` пока не сделана.

Корень у всех цепочек один: API не проверяет Host/Origin/Fetch Metadata и не требует
токена, `readBody` разбирает JSON при любом `Content-Type` (в том числе `text/plain`,
который чужая страница отправляет без CORS preflight), а несколько маршрутов запускают
процессы. Ответ чужой странице не нужен — достаточно побочного эффекта.

Также без побочных эффектов кода, но через ту же границу: `POST /api/install` ставит
глобальный npm-пакет, `/api/mkdir` создаёт папки в любом месте, `sessionsDir` из
`/api/settings` направляет `/api/session/delete` на произвольный каталог.

Порядок исправления: (1) единая проверка Host + Origin/`Sec-Fetch-Site` для **всех**
`/api/*`, включая GET, и `Content-Type: application/json` для JSON-тел — **сделано**;
(2) `openclaudeCmd`, `env` и `sessionsDir` — остаётся запрет `NODE_OPTIONS` и похожих
переменных загрузки кода; (3) `open-folder` — только каталоги, `open-terminal` —
`spawn` с массивом аргументов без сборки строки — **не сделано**; (4) запуск CLI без
`shell: true` — **сделано** (argv + stdin pipe, `.cmd` через `cmd.exe`). Тест цепочки
№ 1 остаётся в release gate как регрессионный.

## Дополнения к плану безопасности

### P0 — секреты в `/api/state`

`server.js:360` возвращает `config.env` целиком. Поле password в интерфейсе не
защищает ключ, уже переданный браузеру. В обычном состоянии отдавать маски/признак
наличия значения, а не секрет. Для произвольных env-переменных не полагаться только
на имена `*_KEY`: неизвестное значение также может оказаться секретом.

Полное значение выдавать только по отдельному явному запросу пользователя
(«Показать»), после общей защиты API от чужих Origin/Host и межсайтовых запросов.
Обычная загрузка формы не должна автоматически вызывать раскрытие. Ответ раскрытия
не кешировать и не журналировать. Это уменьшает раскрытие ключей браузеру, но не
шифрует `config.json` и не защищает от процесса с правами того же пользователя.

Область изменения: `/api/state`, отдельный маршрут раскрытия, `/api/settings`,
`fillSettingsForm`, `addEnvRow`, `envRows`, `saveSettings`, переключение пресетов и
проверка соединения. Сохранение формы без изменения ключа должно оставлять исходное
значение на сервере; маска не должна записываться как ключ. Замена и удаление —
явные отдельные состояния, а не попытка угадать их по строке маски.

### P1 — безопасные встроенные настройки

Привести `DEFAULT_CONFIG` в `server.js:28,37–38` к `config.example.json`:
`permissionMode: 'default'`, `maxTurns: 10`, `maxBudgetUsd: 1` вместо
`acceptEdits` и двух нулевых лимитов. Согласовать fallback в UI и документацию.

Новые значения действуют для отсутствующих настроек; явно сохранённые пользовательские
значения, включая осознанно выбранные нули, не переписывать молча. Проверить старт
без `config.json` и с частичной конфигурацией. Лимиты передавать CLI; фактическое
соблюдение бюджета зависит от поддержки выбранным CLI/провайдером и требует отдельной
интеграционной проверки, одного значения в UI недостаточно.

## Критерии готовности и обязательная проверка

Каждый пункт безопасности закрывается только когда соответствующая проверка
в `npm run test:security` становится зелёной на исправленном коде. Сначала
воспроизвести дефект красным тестом; не подменять исправление ослаблением assertion,
`skip`, `todo` или `continue-on-error`. При этом `npm run check` и `npm test` также
должны проходить, включая обычные легитимные запросы UI.
Сейчас 7 из 7 проходят; строки «маскирование секретов» и «безопасные defaults»
описывают ещё не реализованную работу.

| Пункт | Проверка/критерий в `npm run test:security` |
|---|---|
| Чужой Origin | Существующий `rejects cross-origin settings writes`: 403, конфигурация не меняется; добавить проверку отсутствия побочного эффекта |
| Чужой Host | Существующий `rejects untrusted Host headers`: 403; заголовок реально отправляется через `node:http`, ожидаемый loopback Host работает |
| Перезапись файла | Существующий `upload never silently replaces an existing file`: содержимое сохраняется; дополнить проверкой 409 и успешной загрузки нового файла |
| Junction и границы workspace | Существующий `directory junction cannot escape the selected workspace`: отказ; добавить загрузку через junction с проверкой отсутствия внешней записи |
| Аргументы CLI | Существующий `CLI receives a path with spaces as one argument`: точный argv; дополнить Unicode, кавычками и метасимволами без выполнения внедрённой команды |
| Пустая рабочая папка | Существующий `file browsing requires an explicit workspace`: 400; добавить аналогичный отказ загрузки без записи |
| Цепочка запуска чужого скрипта | Существующий `cross-origin upload + settings + GET /api/check cannot execute code`: файл-маркер не создаётся; защита покрывает и GET-маршруты с побочными эффектами |
| Маскирование секретов — тесты ещё добавить | Синтетические секреты отсутствуют в обычном `/api/state`; явное разрешённое раскрытие возвращает нужное значение, чужой запрос отклоняется; сохранение неизменённой формы не заменяет ключ маской, замена и удаление работают |
| Безопасные defaults — тесты ещё добавить | Без конфигурации и при пропущенных полях получаем `default`/10/$1; mock CLI получает соответствующие флаги; явные сохранённые настройки не меняются |

Для дополнительных P1/P2 нужен собственный регрессионный тест в подходящем наборе;
проверки сохранности данных и границ доступа включать в `test:security`. Пункт без
проверенного критерия не считать завершённым.

Сейчас `.github/workflows/ci.yml` уже запускает job `security` на push и pull request
без подавления ошибок. Когда весь расширенный набор пройдёт, после публикации
репозитория назначить этот check обязательным для `main` в GitHub Rulesets/branch
protection. Проверить, что PR с намеренно падающим security-тестом нельзя слить,
а зелёный PR проходит этот gate. Наличие job в YAML само по себе не запрещает merge.
Настройка required check ещё не выполнена: удалённого репозитория пока нет.

Новые пункты и дополнительные assertions здесь — план, не реализованные исправления
и не уже написанные тесты. Результаты существующих запусков приведены ниже.

## Находки внешнего ревью (перепроверены по коду)

Ниже только пункты, которые подтверждены чтением кода или отдельным запуском.
Приоритеты местами изменены относительно исходного ревью; причина указана.
Пункты, которые уже есть выше (HTTP-граница, shell, загрузка, junction, пустой
workspace, секреты в `/api/state`, `openclaudeCmd`/`env`/`sessionsDir`,
open-terminal/open-folder, конфиг, SSE, память, порт), здесь не повторяются.

### P1

- **Проверка соединения подменяет текущий чат.** `/api/test-connection` идёт через
  `startClaudeRun` без resume, а обработчик `result` безусловно записывает
  `session_id` в `config.sessions` текущей папки. Следующее сообщение пользователя
  продолжит тестовый чат «ответь одним словом: ок» вместо его собственного
  (`server.js:470–475`, `198–201`). Исправление: флаг «не сохранять сессию» для
  тестового запуска. Тест: после test-connection `/api/state.session` не меняется.
- **Двойная отправка.** `send` проверяет `state.running`, но выставляет его только
  после `await saveSettings(...)`; два быстрых Enter запускают два процесса, второй
  поток SSE перетирает первый (`public/app.js:372–386`). Блокировку ставить до первого
  `await`. Поле ввода очищается до ответа `/api/run`, при ошибке текст теряется.
- **«Новый чат» во время работы.** `newChat` очищает ленту и сессию, но не
  останавливает запуск: события старого процесса дописываются в новый чат, а его
  `result` снова сохраняет старую сессию (`public/app.js:431–440`). Останавливать run
  или блокировать кнопку на время работы.
- **«Продолжить» сравнивает пути сырой строкой.** `continueLast` сравнивает
  `s.cwd` и введённую папку через `toLowerCase()`; хвостовой `\`, `/` вместо `\` или
  относительный путь дают «прошлых чатов нет» (`public/app.js:447`). Нормализовать
  путь на сервере (`path.resolve`) и сравнивать уже его.
- **Остановка сервера.** Нет обработчиков SIGINT/SIGTERM: при Ctrl+C дочерние CLI
  могут остаться, временные файлы сообщений не удаляются (`server.js`, нет
  `process.on`). Гасить активные runs и чистить tmp при выходе.
- **Нет отмены у login/install/проверки соединения.** `/api/stop/:runId` уже
  существует, но в UI кнопка «Стоп» есть только у чата (`public/app.js:421, 874`).

### P2

- **Статика: проверка через строковый префикс** (`server.js:675–676`,
  `filePath.startsWith(PUBLIC)`). Перепроверено: пример `/../public2/x` из исходного
  ревью не работает (URL-парсер нормализует `/../`), но работают закодированные
  разделители `/..%2fpublic2%2fx` и `/..%5cpublic2%5cx` → `<корень>\public2\x`.
  Выход возможен только в соседние папки, чьё имя начинается с `public`; сейчас таких
  нет, `config.json` так не читается. Поэтому P2, а не P0. Исправление в одну строку:
  `path.relative(PUBLIC, filePath)` не должен начинаться с `..` и не быть абсолютным.
- **`renderMd`** применяет `**жирный**` и ссылки внутри уже собранного инлайн-кода
  (`public/app.js:76–81`). Экранирование не ломается, только отображение.
- **После F5 лента чата пуста**, хотя сессия помнится. Отдельный endpoint с последними
  сообщениями из JSONL сессии.
- **`start-ui.bat`** не проверяет major-версию Node (нужна 22+); если UI уже запущен,
  печатает «Сервер остановлен» вместо «UI уже запущен».
- **Заголовки** `X-Content-Type-Options: nosniff` и базовый CSP — после P0.
- Кнопка «Копировать» у блоков кода.

### Не принято или понижено

- Отдельный P0 «статика через префикс» → P2, см. выше.
- P0 «опасные настройки» и «open-terminal/open-folder» как самостоятельные пункты:
  после общей HTTP-границы это защита в глубину, поэтому они остаются в разделе
  «Цепочки выполнения кода» и исправляются следом за границей, а не отдельными P0.
- Случайный токен сессии: не обязателен при проверке Host + Origin/`Sec-Fetch-Site` +
  `application/json`. `EventSource` не умеет передавать заголовки, токен пришлось бы
  нести в query string. Вернуться к нему, если проверки заголовков окажется мало.
- «Ограничить права на `config.json`»: на Windows `chmod` почти не действует, нужны ACL.
  Низкая ценность для однопользовательского ПК; не в плане.

## Следующие улучшения по исходникам (пока без отдельных runtime-проверок)

### P1 — надёжность и сохранность

- **Сохранение конфигурации:** `loadConfig` скрывает любую ошибку, затем старт сервера
  вызывает `saveConfig`. Повреждённый JSON может быть заменён настройками по умолчанию.
  Читать с различением ENOENT/ошибки JSON, сохранять атомарно через временный файл и rename,
  возвращать ошибку записи вызывающему API, не сообщать ложное `ok`.
- **Ошибки сохранения в UI:** `saveSettings` поглощает ошибку, а `send` и
  `testConnection` продолжают запуск. Возвращать результат/исключение и останавливать
  отправку до успешного сохранения. Не терять введённое сообщение.
- **SSE:** при автоматическом переподключении остаётся первоначальный `from`, нет
  SSE `id`/`Last-Event-ID` и защиты UI от повторов; `onerror` ничего не делает.
  Добавить возобновление по seq и видимый статус обрыва.
- **Завершение CLI:** финальный JSON без перевода строки проходит другой путь парсинга
  и не обновляет стоимость/сессию так же, как обычный `result`. Использовать один обработчик строк.
- **Занятый порт:** `listenOn` считает любой HTTP-ответ на `/api/state` чужого процесса
  доказательством запущенного UI. Проверять сигнатуру приложения и timeout; иначе пробовать следующий порт.
- **История другого проекта:** выбор сессии в `openHistory` не меняет workspace.
  Перед продолжением сверять `s.cwd` и выбранную папку, предложить переключение.
- **Память сервера:** завершённые `runs` и `events` не очищаются. Ограничить срок/число
  завершённых запусков и объём буфера, сохранив возможность reconnect.
- **Прерванные загрузки:** обработчик `error` разрешает ожидание тела; неполные chunks
  могут дойти до записи. Писать только после полного запроса, не сохранять оборванные файлы.

### P2 — удобство и доступность

- Модальные окна: роли dialog, заголовки, управление фокусом и возврат фокуса после закрытия.
