# Аудит чувствительных данных

Проверено: 2026-10-23. Область — рабочее дерево, индекс Git и локальные файлы,
исключённые из Git. На момент проверки в репозитории не было ни одного коммита,
поэтому чистить историю не требовалось.

## Вывод

В файлах, которые попадают в Git, API-ключей, токенов, паролей, адресов почты и
персональных данных не найдено. Чувствительные данные присутствовали только в
локальных файлах вне Git; личные документы вынесены за пределы папки проекта.
Репозиторий можно публиковать как **прототип**: ограничения безопасности описаны в
[REVIEW.md](REVIEW.md) и [SECURITY.md](../SECURITY.md).

## Что и как проверялось

| Область | Как проверялось | Результат |
|---|---|---|
| Индекс Git (`git grep --cached`) и рабочее дерево | шаблоны ключей: `sk-…`, `AKIA…`, `ghp_/gho_/ghs_…`, `xox?-…`, `BEGIN … PRIVATE KEY`, `Bearer …` | совпадений нет |
| Присваивания секретов | `(api_key\|secret\|password\|token\|credential)\s*[:=]\s*"…"` | только поле ввода в UI и имена переменных, реальных значений нет |
| Строки высокой энтропии | base64/hex длиной 40+ символов | совпадений нет |
| Персональные данные | email, телефоны, ФИО, «паспорт/СНИЛС/ИНН/договор» в файлах Git | совпадений нет |
| Локальные пути и имена | `F:\Test`, `C:\Users`, `os.homedir()` | в файлах Git только `os.homedir()` — это код, а не данные |
| Внешние адреса | все `http(s)://` в коде и разметке | только `127.0.0.1`/`localhost` и ссылка на проект openclaude; телеметрии и CDN нет |
| История Git | `git log`, `git rev-list --all` | коммитов нет, переписывать нечего |

Ограничение метода: поиск по шаблонам не доказывает отсутствие секретов. Он не
заменяет отзыв ключа на стороне провайдера, если ключ когда-либо попадал в переписку,
скриншот, архив или резервную копию.

## Локальные файлы вне Git

Эти файлы исключены `.gitignore` и в коммит не попадают. Что с ними сделано:

| Файл | Что внутри | Действие |
|---|---|---|
| `config.json` | абсолютные пути `F:\Test`, UUID сессий, ключ-заглушка `ollama` | оставлен на месте (нужен для запуска), исключён из Git |
| `test/demo-workspace/КП_Поляков_Советская 47.pdf` | фамилия и адрес — персональные данные | перемещён в `F:\Test\_openclaude-ui-private\pii\` |
| `docs/screenshots/*.png` | реальные пути `F:\Test\…`, имена прошлых чатов | перемещены в `…\screenshots\` |
| `test/s4.txt` | имя пользователя Windows и пути к конфигурации CLI | перемещён в `…\logs\` |
| `test/run3.json` | путь `F:\Test` и текст ручного запроса | перемещён в `…\logs\` |
| `test/fake-config/**` | синтетические сессии, вымышленные данные | оставлены, исключены из Git |
| `test/demo-workspace/{README.md,src/app.js}` | безобидные демо-файлы | оставлены |

`config.json` по устройству приложения хранит ключи API открытым текстом (см.
[SECURITY.md](../SECURITY.md)), поэтому он исключён из Git и не должен попадать в
архивы, issue и скриншоты. Если в нём когда-либо был настоящий ключ — отзовите его у
провайдера.

## Заглушки, которые не являются секретами

- `public/app.js`: пресет Ollama — `OPENAI_API_KEY: 'ollama'` и
  `OPENAI_BASE_URL: 'http://localhost:11434/v1'`. Это общепринятая заглушка локального
  Ollama, а не действующий ключ.
- `public/i18n.js`: `C:\Users\Вы\МойПроект` — подпись-пример в подсказке интерфейса.

## Рекомендации после публикации

1. Включите на GitHub **Secret scanning** и **Push protection**
   (Settings → Code security): GitHub заблокирует пуш с распознанным ключом.
2. Не выполняйте `git add -f` для путей из `.gitignore`.
3. Скриншоты для README снимайте на синтетических данных (`D:\demo\project`,
   вымышленные имена), иначе пути и имена чатов снова попадут на GitHub.
4. Ключи храните только в `config.json` или переменных окружения; при утечке
   отзывайте ключ у провайдера — удаление из Git не отменяет утечку.
5. Периодически повторяйте проверку:

   ```sh
   git status --short --ignored
   git grep -nE "sk-[A-Za-z0-9_-]{16,}|gh[pousr]_[A-Za-z0-9]{20,}|AKIA[0-9A-Z]{16}|BEGIN [A-Z ]*PRIVATE KEY"
   git log -p | grep -nE "sk-[A-Za-z0-9_-]{16,}|BEGIN [A-Z ]*PRIVATE KEY"
   ```
